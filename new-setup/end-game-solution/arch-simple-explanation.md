Think of this document as the blueprint for a **"one-click store setup system"** for your ERP/OMS.

Today, when a new Shopify client comes in, engineers manually create facilities, mappings, locations, permissions, environment variables, etc. This proposal automates that entire process.

---

# The Big Discovery

While investigating the Moqui framework, you found something important:

**Moqui does not fail when the same record already exists.**

Instead, it does:

```text
Record exists?
 ├─ No  → INSERT
 └─ Yes → UPDATE
```

So if a client configuration tries to load a record that already exists, Moqui simply updates it.

This behavior is called **idempotent upsert** and is the reason the automation is possible.

# Two Existing Architectures

## Setup A (Modern Moqui)

```text
Framework
   ↓
mantle-udm
   ↓
Client Component
```

Good things:

* Components load in dependency order.
* Framework data loads first.
* Client data loads later.
* Foreign key issues are rare.

Example:

```text
Moqui Base
   ↓
mantle-udm
   ↓
gorjana-maarg
```

This is the preferred architecture.

---

## Setup B (Legacy OFBiz)

Everything is loaded together.

```text
A1_Common.xml
B1_Product.xml
C1_Facility.xml
D1_Store.xml
```

The only thing controlling load order is filename prefixes.

If the order is wrong:

```text
Store references Facility
Facility not loaded yet

→ Foreign Key Error
```

So Setup B is more fragile.

# The L1-L4 Data Model

You discovered that all setup data naturally falls into 4 layers.

---

## L1 = Platform Data

Things every store needs.

Examples:

```text
UOM
Facility Types
Status Types
Order Types
```

Owned by framework.

Never customized per client.

---

## L2 = Integration Data

Things needed for Shopify integration.

Examples:

```text
Shopify mappings
Sync jobs
System services
```

Shared by all Shopify stores.

---

## L3 = Client Data

Store-specific setup.

Examples:

```text
Facility
Warehouse
Contact Address
Store Settings
Return Location
```

Different for every client.

This is what the installer generates.

---

## L4 = Secrets

Sensitive information.

Examples:

```text
API Keys
Access Tokens
Passwords
Webhook Secrets
```

Never stored in XML.

Stored in:

```text
.env
```

files instead.

---

# Entity Tiers

Not every table should be touched.

You classified them into 3 categories.

---

## Tier 1 = Core System

Examples:

```text
ProductCategoryType
VarianceReason
PartyRelationship
```

These are ERP foundations.

Installer should not modify them.

---

## Tier 2 = Configuration Tables

Examples:

```text
Facility
ContactMech
ProductStoreSetting
ShopifyShopTypeMapping
```

These are safe to create/update.

Installer focuses mainly on these.

---

## Tier 3 = Live Business Data

Examples:

```text
Orders
Shipments
Inventory
```

Generated by Shopify syncs.

Installer never touches them.

# What Happens During Data Loading?

When Docker starts:

```text
Docker
 ↓
MoquiStart
 ↓
EntityDataLoader
 ↓
XML Files
 ↓
Database
```

For every XML record:

```text
Read XML
 ↓
Find Primary Key
 ↓
Does record exist?
```

If not:

```text
INSERT
```

If yes:

```text
UPDATE
```

That's the entire magic.

# Proposed Workflow

## Stage 1

Load framework data.

```text
seed
seed-initial
```

Creates ERP foundation.

---

## Stage 2

Load Shopify integration layer.

```text
Shopify mappings
Jobs
Services
```

Creates connector machinery.

---

## Stage 3

CLI asks questions.

Example:

```text
Store Name?
Shopify Shop ID?
Return Warehouse?
Address?
```

Engineer simply fills answers.

---

## Stage 4

System generates XML automatically.

Example:

```xml
<Facility facilityId="STORE_001"/>

<ContactMech contactMechId="ADDR_001"/>

<ShopifyShopTypeMapping .../>
```

Then loads it.

Moqui automatically:

```text
INSERT new records
UPDATE existing records
```

No manual editing needed.

---

## Stage 5

Add secrets.

```text
SHOPIFY_API_KEY=
SHOPIFY_ACCESS_TOKEN=
WEBHOOK_SECRET=
```

into:

```text
.env
```

Store goes live.

# Why This Is Safe

### Problem: Duplicate Data

Without upsert:

```text
Record already exists
↓
Crash
```

With Moqui:

```text
Record already exists
↓
Update record
↓
Continue
```

No crash.

---

### Problem: Missing Facility

Current risk:

```text
Store created
Warehouse forgotten
```

Installer solves this by forcing user to answer warehouse questions.

---

### Problem: Missing Permissions

Current risk:

```text
Store exists
User can't access UI
```

Installer generates artifact group mappings automatically.

---

### Problem: Secret Leakage

Current risk:

```text
API keys inside XML
```

Installer keeps secrets only in:

```text
.env
```

files.

# One-Sentence Summary

The proposal is essentially a **"Shopify Store Installation Wizard"** that asks a few questions, automatically generates the required Moqui setup data (Facilities, Addresses, Mappings, Permissions), loads it using Moqui's built-in insert-or-update behavior, stores secrets separately in `.env`, and brings a new client store online with minimal manual work.
